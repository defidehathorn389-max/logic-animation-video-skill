# 墨问通用制作标准

适用于今后任何模型。此文记录可复用的默认规范；具体任务选择及后续变更读取统一私有进度库。不要把历史示例的近似字幕、旧人物、右上标语重新带回。

## 1. 品牌与人物分场景使用
- 品牌只有“墨问”，不再二选一。成熟、酷、非真人感；拒绝幼稚大头墨滴，不模仿别人的角色或署名。
- 主页头像/背景可以保留精细水墨美术；视频正文与片头片尾统一灰底、简化黑白线稿人物、黄色逻辑道具。不把写实山水水墨片头硬接简笔画正文。
- 视频NPC身份标识：无脸黑头、一道斜白线、高领、黑白长衣，成人比例。讲解/思考/指向/摊手揭晓四姿态由私有项目配置提供路径。
- 全程单一姿势不合格；按提问、分析、操作解释、揭晓切换关键姿态。不得用整个人物晃动、漂浮代替表演。
- 使用多关键姿态时，不得宣称已经完成连续关节绑定。拿取、点火、翻面等角色动作必须有真实接触点和道具状态支持，没实现就不宣称实现。
- 墨问为讲解者。蒙眼/失明等故事中的参与者不能因为讲解者可见图而获得不允许的信息。

## 2. 画面与字形
- 默认16:9、1920×1080、30fps、H.264/yuv420p/AAC/faststart。核心几何与字体直接绘制到1080p，不以单纯放大编码冒充原生细节。
- 背景 #bdbdbd，轮廓 #252525，重点 #f7ca54，白色区域 #f8f8f5。黄色是强调色，不是所有具象物件的唯一颜色；可使用低饱和木色、灰蓝、植物绿和自然肤色，限制同时出现的主色数量并保持黑白灰画面层级。
- 正文左上只放“墨问”两字，不带编号、斜杠或系列副名；正文右上不放“理想化逻辑题”等常驻长标语。必要题设、安全边界仍须在正文相关场景或发布简介中清楚给出。
- 所有精确文字、数字、数量图和公式用代码绘制。不要采用生图里看似正确的随机文字/硬币数量。
- 明确选择简体中文字形。NotoSansCJK的TTC合集要验证具体face，当前环境 SC 为 index=2；不能盲用默认JP face。环境变更时重新核实，不能永久假定index=2适合任意字体。
- 全文检查标题、字幕、角标、计数、封面、片头片尾及发布简介中的错别字和条件矛盾。“墨”为U+58A8；字形地区差异不等于源字符编码错误。

### 2.1 小屏可读性门禁（用户审片反馈沉淀，2026-09）
- 讲解者形象默认不常驻正文；舞台主体居中放大。
- 同屏 ≤2 行大字（≥52px@1080p），字幕 ≥72px；不出现小字规则卡/公式/汇总板。
- 交付前把 ≥5 个关键帧缩到 640×360 复查，任一数字/文字看不清即不通过。
- 长段配音（>60s）逐字对齐可能在中途失锁：按句群 ≤40s 分段合成再对齐，并检查零时长字与事件锚单调。

### 2.2 交付前终检（Final Quality Gate，用户审片反馈沉淀 2026-09）
交付前必须逐项打勾并写入 QA 记录，任何一项不过即不交付：
1. **插画而非几何图形**：每个关键状态（题设物件、每一步操作后的状态、结论态）都是生成插画（同一风格、同一物件跨状态一致），不能用代码圆/矩形代替实物；代码只画标注（数字、箭头、勾叉、框）。
2. **角色有脸有反应**：故事角色有简单五官与至少两种表情态（平静/困惑或惊讶），并在关键节拍切换；不用“无脸复制人”。
3. **克制的颜色**：颜色只点缀关键物件（1–2 处，如果酱、药片），人物与场景保持黑白线稿；状态色（红/绿/黄）只用于标注。全灰单调与整幅上色都不过。（2026-09-21 用户补充：**物品颜色可以适当加点缀**——题设道具允许低饱和本色，如饼的麦黄、锅的木柄棕；仍限 1–2 种主点缀色，人物服装保持黑白，颜色不抢黑白灰层级。）
4. **场景底**：物件放在桌面/地面/场景底上，不悬浮。
4b. **计数正确性**：凡表达数量的生成图（N 块、N 个、N 条线）入片前必须逐张人工数数并记录；生成模型常少画/多画。数不对就重生成，或在整体图上由程序精确绘制分割线。
5. **参考对照**：把 ≥4 张成片关键帧与参考账号同类节拍的帧并排（`tools/study_frames.py` 或手工拼图），逐项对比人物/物件/颜色/文字量/结尾，写出差距与处置。
6. 小屏可读性（§2.1）、逻辑断言、validate_video、响度 —— 沿用。
7. 片头片尾按项目品牌决定（可无片尾）；若无片尾，正文最后一句后留 0.6–1.0s 静止再结束。

### 2.3 交付前自审（Self-Review，2026-09-20 沉淀）
用户的反馈不应是第一道质检。每次交付前，制作者必须**自己先当审片人**，逐帧看完事件帧并按下表量测，不合理处自己改掉再交付。以下每一条都来自真实返工：

| 坑 | 症状 | 规则 |
|---|---|---|
| 每个状态各生成一张图 | 同一物件在不同状态里大小、风格、盘子都不一样；“一刀两块”被画成“挖走一块” | **单源派生**：只生成 1 张基础物件图，量测其几何（椭圆中心/半径、腰线、壁线），所有切割/拆分/移动状态由程序在同一张图上切片、错位、补截面得到。生成图数量 = 物件数，不是状态数 |
| 场景底只是“放上去” | 蛋糕悬在桌前、脚下无接触 | 量测底图可放置区（如桌面行区间），物件底边必须落在区间内，把量测值写进 state-model |
| 动作特效手写坐标 | 刀光/切线与图里的切缝不重合，刀穿桌 | 动作路径必须由同一几何函数生成（切缝 = 刀路），运动终点受实体边界钳制 |
| 生成的计数图不数数 | “7 块”图只有 5 块 | 见 §2.2 4b；或改成程序精确绘制 |
| 布局靠眼睛 | 字幕压住角色 | 渲染器记录所有元素包围盒，`--preview` 自动报告与字幕带/彼此的重叠，为零才交付 |
| 只看事件帧 +0.9s | 动作中途的错误（刀反向、穿模）看不到 | 事件帧至少看 +0.25s 与 +0.9s 两拍；有运动的事件再加中途帧 |
| 可切/可拆物件带装饰 | 蜡烛正好在切缝上被劈成两半，开场就自相矛盾 | 生成基础物件时，装饰（蜡烛/樱桃/logo）不得压在任何后续切缝/拆分线上；能省则省，或放进某一块的内部 |
| 修订时顺手改了已批准的东西 | 用户已认可的字幕样式/版式在修订版里被换掉，招致返工 | **修订只改反馈点**：已批准的元素（字体、字幕动效、配色、版式）一律锁定；想改必须单独提出并获批准，不能夹带 |
| 屏幕文字多色（黄/绿/灰/红混用） | 用户反馈“字体颜色有点花” | **屏幕文字只用黑 + 唯一强调色（默认红）**：标题、标签、编号一律黑；只有结论/警告/关键数字用强调色；圈选/高亮框同色。参考账号即黑字 + 偶尔红。字幕带的已批准样式不在此列（锁定） |
| 物件从 0 缩放弹入 | 开场出现一团小重影 | 大物件用原位淡入或从 0.85 弹入，不从 0 缩放 |
| 自审只做“抽 4 帧看看” | 用户一眼看出多处不合理 | 自审产出一份量测表（问题/量测值/根因/处置），存进度库；没有表就没有自审 |

### 2.3a 试片无豁免（2026-09-21 沉淀，020 试片整版被废）
真实返工：020 r5 文案、配音、背景、角色都已过审，但"试渲染"版把组件全部用代码矩形/色块手绘（统计块、比例条、50/50 滑条）、屏幕文字黄红灰多色、字幕不按品牌锁定样式——用户一句"画面、组件、字幕完全不符合 skill 标准"整版废弃，前面的对齐渲染工时全部白费。规则：
1. **"试片"只是"未终审"，不是"可以先降标准"**：任何呈给用户看的渲染（哪怕叫 trial/preview），组件、配色、字幕、版式必须与终版同标准；想省时间只能降时长（渲染片段）或降分辨率预览自查，不能降规范。
2. **渲染前先过组件清单门**：列出全部画面元素，逐个标注"生成插画抠图 / 代码绘制"；代码绘制仅限精确文字、数字、箭头、勾叉、框线等标注类（SKILL.md L20、§2.2-1）。清单里出现代码手绘的"物件/面板/图表主体"即不许开渲。
3. **字幕样式从 branding.json 读取**，渲染器不得自带一套字幕配色；渲染前 diff 一次实际参数与 branding 锁定值（72px 白字黑描边逐字黄高亮）。
4. 已过审的上游产物（文案/配音/背景/角色）与渲染版式是两回事；画面废弃≠上游废弃，先问用户废弃范围再动手。

### 2.3b 文案逻辑门（Script Logic Gate，2026-09-20 沉淀，**过门才允许生成语音**）
真实返工：016 写成"一个人相亲要凑两双同色袜子"——答案 6 没错，但前提站不住（一个人只穿一双），观众第一句就出戏。规则：

1. 文案定稿后、TTS 之前，逐条回答并写进 `script.json.logic_check`：
   - **前提合理**：情境里的每个要求都有生活理由（要两双 → 两个人；要 N 个 → 谁用）。
   - **规则自洽**：规则、赌注、追问互不矛盾（"人走了"和"再加一问"要能同时成立）。
   - **答案正确**：暴力/穷举或手推最坏路径验证，结果写进 logic_check。
   - **通俗可懂**：一句话能向外行复述题目；数字口语化。
2. 任一条不过 → 改文案，**不生成语音**、不渲染。语音生成是逻辑门之后的第一步。
3. 改前提时同步检查：屏幕文字、封面文案、发布文案、追问段落是否还成立（全局 grep 旧措辞）；render.py 的 t_of 锚点短语也要全部核对存在。
4. **文案先审后配音**：前提被质疑过的题，或用户提出"先看文案"，必须把文案草稿（含逻辑门四项自查、字数/时长预估、幽默点清单）作为文件交给用户，获批后才 TTS。只重录改动段落，未改段落沿用原音频。
5. 前提修补别"加人"：为凑"两双"引入第二个人物（室友）反而更别扭；优先用同一人物的自然理由（穿一双+备用一双）。幽默每段最多一处，不进结论句。
7. **逐句模拟叙述，不只核数字**（017 r1/r2 真实事故）：答案 80% 算对了，但文案把两条线写反（女友 :00、妈 :02 → 实际 80% 去女友家），三轮自审都没发现，因为自审只核"2:8"这个数。规则：逻辑门脚本必须**按文案原话建模**（谁在 :00、谁在 :02、到站落在哪段先来谁），对每个具体时刻各举一例（如到站 :01 / :05）输出"先来谁"，与文案该句逐字比对；并把这些例句写进 `script.json.logic_check.sentence_checks`。渲染器常量命名要带语义（`MOM_OFF/GF_OFF`），避免"参数叫 mom_off 实际控制女友窗口"。
6. 第二人称应帮助观众进入具体选择，不用口头反复加“你”冒充代入感。反馈密度按 `light-puzzle-experience.md`：每15秒一个包袱或爽点，以观看全长及事件空档核对；旧“约4个笑话/分钟、100秒约7梗”的独立配额由此替代。每段至多一处刻意笑点，证明与最终结论不硬塞梗；证明的认知推进可计爽点。

### 2.3c 屏幕文字可读性
- 舞台底是浅灰，**屏幕文字禁用白色**（"停电了"白字曾被反馈看不清）；正文黑，强调红。
- 生成的人物/物件 PNG 透明边距很大，包围盒重叠检测会漏判——文字与人物图重叠必须**看图确认**，或把文字放到人物侧边而不是头顶。
- 预览帧文件名含时间戳；重新对齐音频后先 `rm -rf checks` 再预览，避免看到旧帧。

- 生成的场景底图（如站台）线稿太重会压过前景：合成时把线稿 alpha 乘 0.35–0.4，前景人物/道具保持全黑线。
- 人物在画面中央时，任何标题都不要放在中轴线上方——统一"人物偏左、文字偏右"或反之；包围盒检测对人物 PNG 无效，必须看图。
- 数据图（时间轴/钟面）上的图标沿圆周/轴移动时，会经过底部说明文字：说明文字放在图的左上/右上，不放正下方。
- 封面道具不要出现无内容的纯黑块（空屏/空框）：屏幕要有字或点亮；允许 1–2 处小面积点缀色（红条、黄灯），主体仍黑白。
- 交通工具类道具入场必须完整可见且"落在"它该在的面上（轨道/路面）：先量测底图轨道区的 y，再把车底边钳到该 y；不能被画框裁掉车头。

### 2.3d 开场前 5 秒门槛（2026-09-20 沉淀，用户问"能保证前 5 秒抓住观众吗"）
不能保证留存，只能保证以下四项可量测条件全部成立，并在 `checks/enc-first6s.jpg`（成片 2fps 抽 6 秒）上人工核对：
1. **首帧含题设道具**（抽屉+袜子），不是人物独白静帧；
2. **≤1s 发生一次画面事件**（灯灭压暗/门关/道具摊开），可配一声短低频"咔"；
3. **前 5s 台词含具体数字**（三十只、各十）；
4. **前 5s 无纯人物静帧**；提问仍落在 15–20s。
灯灭压暗时屏幕字可用白色（暗底），恢复亮度后立即回黑；这是"屏幕文字禁白"的唯一例外。

### 2.3e 开头题设双通道门（2026-09-21 沉淀，021 r2 教训）
真实返工：r2 开头"打脸前置"梗做足了，但前两句只有"十二分钟/九分钟"数字对喷，烙饼、锅容量、每面时长第三句才出现——纯音频观众前 4 秒不知道在干什么。规则：
1. **首句必含任务锚**：题设三要素（道具、约束、目标）至少一个落在第一句台词里（如"三张饼"），不能全靠首帧画面补——音频是单通道场景（锁屏听/倍速刷）。
2. 梗、赌注、答案前置都不豁免此条；冲突时优先改梗的措辞，不删任务锚。
3. 自查方法：把 01 段前两句念给不知道题目的人听（或自问），能答出"这是在干什么"才过。
4. **轻解谜开场优先**：具体处境/愿望与核心矛盾→低负担的选择→必要条件随对象/动作呈现→完整首问≤20秒。首句仍要有任务锚，但不再强制一口气说完全部约束或用清单句开头。开头的包袱服务任务；规则必须在需要观众据此推理前清楚交代。详见 `light-puzzle-experience.md`。

### 2.4 文案对标（参考账号文案结构，2026-09-20）
参考账号 6 篇 ASR 量测出的固定结构，新期文案逐项对照：
1. 一句钩子（≤25 字）：第二人称 + 极限情境 + 赌注；不要"生日会上，一个蛋糕"式的第三人称旁白。
2. 必要条件按理解顺序呈现，再给一个具体选择（可给A/B）；不为固定模板凑三句规则。
3. 错误尝试只在有信息增量时使用，优先短反例；不强制长篇错误路线，不假定多数人答错，不羞辱观众。
4. 揭晓一句一个动作，数字口语化；句长 ≤15 字，禁"真正的问题不在…而在…"式书面转折与解释性从句。
5. 一句原理 + 一句生活迁移。
6. 收尾口令：短、对仗、可截图（"记住：…"）。
7. 语速 320–340 字/分钟；90–120s。文案写完先按此 7 项自评，再进 `script_budget.py`。
8. **难度与赌注门槛（2026-09-20，016 r1 教训）**：题面若观众在 3 秒思考拍内能自行得出答案即偏易，必须升级——参考账号 20/54 期在揭晓后"再加一条规则"做第二层递进，39/54 期赌注为"死/毒/枪/百万/坐牢"级；新期至少满足：常见错答与真答差距明显 + 一个第二层追问 + 具体可感的赌注（迟到/出局/输钱），不能只靠"一脚黑一脚白"式轻赌注。

### 2.5 三项硬约束：语速 / 文案风格 / 时长 必须与参考账号一致（用户强要求，2026-09-20）
不满足任一项不得交付；三项都要在 publish.json 的 `consistency_targets` 里写目标值与实测值。
| 项 | 目标（量测自参考账号 54 篇 ASR） | 怎么保证 |
|---|---|---|
| 音频流水线 | 一次跑完：停顿截 0.2s → tempo → atempo → stable-ts 逐字对齐 → 零时长拆分 → 3s 思考拍插入 | 脚本 `tools/audio_pipeline.py <ep_dir>`（需 script.json + audio/NN.wav；可选 `pause_after` / `pause_seconds` / `pause_cap_s`，见 episode-pipeline 工程坑） |
|---|---|---|
| 语速 | **320–340 字/分**（纯说话段，中位 325） | 1) 先数文案字数 N；2) TTS 后把 >0.2s 的停顿截到 0.2s（TTS 自带停顿常占 20–30%）；3) 需要的 atempo = 截后时长 ÷ (N/325×60)，允许 1.1–1.35；4) 对齐后用逐字时间反算实测 cpm 写入 |
| 文案风格 | §2.4 七项结构（第二人称入局、一句钩子、先打脸直觉、动作化揭晓、原理+迁移、口令收尾、句长≤15） | 写完逐项自评；任何一项不满足就改稿，不靠语速补 |
| 时长 | **85–120s**（参考中位 ~120s，短题 85–100s） | 由字数决定：N = 目标秒数 × 325 ÷ 60（90s ≈ 490 字，100s ≈ 540 字）；思考拍 2–3s、句间 0.3s、结尾 0.8s 静止已含在内 |

## 3. 音频、逐字字幕、倒计时
- 优先复用已有干净WAV和已授权音色，不为改画面重新TTS；新配音仍按当前工具规则先选声，旧voice_id不保证有效。
- 先测量实际配音及提速后的音频，再建立共享时间轴。声音、字幕、计数、角色、道具全部使用这条时间轴。
- 字幕必须依据干净配音做中文逐字声学对齐（forced alignment/可靠ASR字时间）。禁止按句时长平均分字，却声称逐字对齐。
- **节奏与发音检查（2026-09-21，用户要求；TTS 提速后、对齐渲染前必做）**：节奏——分段实测 cpm（段字数÷提速后段时长），单段偏离全片中位 >15% 要说明（数字密集段可慢）；审计内部 >0.4s 停顿并说明去留；首问时间用对齐结果复核用户上限；检查峰值/削波。发音——用 ASR 把提速后音频回转写，与原稿逐句比对：同音字差异归 ASR 误差；非同音差异列为嫌疑，必须人工听审；高危词（数字/百分比/年代、多音字如单还差数重倒发看、专名术语）无论 ASR 对错都要人工听一遍。错读/吞字/含混只重录该段，未改段沿用原音频。
agent 无耳代查法（2026-09-21，用户授权agent代听审时用）：发音嫌疑先换大一号ASR模型在raw与提速版各跑一遍，只在提速版出现→重录该段；两版都出现→做隔离探针（把嫌疑词单独合成最小对，如倒输/倒数），探针对了判ASR偏置、错了判TTS前端分词错（换写法或重录）；声调争议看字级F0只作参考（八度跳变常见，不单独定罪）。情感节奏看能量动态（语音段RMS 5–95百分位差应>10dB）、分段语速随内容自适应（数字段慢、钩子段快）、停顿落在标点；三项过判条件通过，成片后用户觉平再换声。
**声音审核步骤（2026-09-21，试制配音必走，顺序执行）**：1.收段——逐段TTS存audio/NN.wav并记raw时长，缺字串段直接重录；2.截停顿——首尾留0.15s、内部>0.3s截到0.22s（audio_pipeline.py标准0.2s，手工与工具二选一、全片统一）；3.定速——按§2.5公式算atempo，>1.3换声，无ffmpeg用WSOLA≤1.25x；4.节奏门——分段cpm偏离中位>15%说明、停顿审计、峰值/削波、首问复核；5.发音门——ASR回转写对原稿，同音归ASR，非同音嫌疑先大一号模型raw/paced对照，仍存疑做隔离探针最小对，高危词必查；6.修段——只重录问题段（版号b/c，最多两版），新版重过4–5步，旧版保留；7.拼盘——按timeline拼narration-trialN.wav（含思考拍/尾停）并写qa-trialN.json；8.裁决——agent先签通过/条件通过及理由，用户终裁（可授权agent代裁），verdict进证据。
- 需要的 atempo >1.3 说明嗓子天生慢：优先换声重录，不硬拉到目标语速（020 教训：raw 约 210 字/分，拉到 325 需 1.33x 不可接受，改截停顿 +1.25x 得约 305 字/分试制）。无 ffmpeg 时允许 numpy WSOLA 代替 atempo（≤1.25x），仍须过节奏门。
- 对齐输入用准确原稿；保留逐字JSON、对齐方法和可疑边界记录。静音要从字范围中剔除，连读/轻声/零时长字应复核。机器估计不是逐字人工听审后的零误差。
- 显示效果：逐字轻弹入，可短暂黄色高亮，保留句尾阅读时间；不要剧烈跳动。导出句级SRT和逐字时间JSON，说明SRT本身不含弹字动画。
- 逐字绘制时所有字形必须共享字体基线，只让当前字叠加已批准的小幅弹动。不能逐个字按自身bbox顶端对齐，否则逗号会悬到行顶，“一”等短字形也会上浮。至少用含句中逗号和短横字形的编码后帧检查基线，修复不改变锁定字号/描边/颜色或声学时标。
- 中间完整3秒“3、2、1”，一秒一拍，配克制提示音。插入静音必须同步顺延后面的所有字幕、旁白、场景和导出数据。
- 片头约1秒、片尾约3秒；正文时长服从内容。历史四片药较短，不为凑满两分钟无意义拉长。
- 音效用于点火/翻面/步骤/揭晓，不每字一响，不喧宾夺主。音效节点也应来自配音和动画实际事件。
- 低调悬疑氛围BGM可用原创合成或有授权素材；不提取参考创作者音轨。约−25dB是本次底乐音源的增益，不是整体−25LUFS或恒定比人声低25dB；注明参考，混音后检查峰值和听感。人声出现时可额外duck约4dB。
- 保留旁白清晰度和结尾尾音；不能把技术解码成功描述成完成了人工听感验收。

## 4. 动画与逻辑不得互相矛盾
- 操作、身份、数量、正反、燃烧状态由同一确定性状态模型生成；计数器取画面实际状态，不独立猜数字。
- 旁白尚在解释初始状态时，画面不能提前完成操作。关键事件锚定配音中的对应词/句，如“翻面”“两头一起烧”“30分钟到了”。
- 区分示意静帧与计时演示。未消耗的静止绳子不挂持续燃烧火焰；如果暂停讲解则明确说明。
- 非匀速绳子左右火头的长度推进速度可不同；同时开始后两端经过的时间相同。不能为了视觉对称强行改成长度匀速。
- 时间刻度与长度刻度分开标注；对称时间条的左右边界必须一致。保留非中点相遇。
- 第二阶段绳子剩余单头时间30分钟，双头各经过δ分钟后剩余30−2δ，累计时间30+δ；δ=15时完成45分钟。
- 硬币题：初始10正面不等于翻面后总正面仍为10。k→10−k，另一堆保持10−k；100个物体身份不丢失，未选90个不翻动。
- 药片题：每一片各分一半到两天，不是随意选四个半片。保留成分均匀/可精确等分的题设和现实安全提醒，不能作为现实用药建议。

## 动态演示与过渡状态验收
- 动态应来自实际推理操作、因果反馈和局部重点，不用人物整体晃动、无关粒子或持续换文字冒充动画。
- 运输、装卸、拿取等题目必须验证完整过渡过程，不只验证起点和终点。对象身份、所在位置、载荷限制和参与者状态应来自同一模型；不能让道具瞬移、复制或悄悄消失。
- 脚部与甲板/地面、手部与桨柄/道具等接触点应共享坐标；有操作者的空载返程不等于无人驾驶。
- 错误方案须明确标注为假设演示；回退后恢复正确初始状态，不混入正式操作计数。局部放大或回放要标明用途，不能让同一物体的第二视图被误读为新增物体。
- 连贯回放也需给装载、移动和卸载留出可见时间。若口播过密，应调整对应回放文案/配音或整体节奏，不把完整动作硬塞进一个字的时间。
- 白色/浅色主体不能与同色特写底板混成一片；导出后复查实际编码帧，而不只检查渲染前截图。
- 逐字对齐出现零时长或异常密集的边界时，记录问题并使用声学信息复核；修复保留方法与范围，不退回按句均分。机器ASR结果不冒充人工听审。

## 8. 形象确认、图片组件关节动画与节奏迭代
- 用户要求先看形象时，先交静态角色/道具提案，明确尚未完成绑定；确认后再制作动作样例和正式视频。旧片接受不等于新形象或修订版接受。
- 生成图片不会自动产生步态。需要生成适于分层的组件，分别准备躯干、上/下肢、手足与必要遮挡补画，或制作一致的关键姿势；关节变换只操纵生成组件，不用代码画细线四肢替代已批准造型。
- 步行动作按位移驱动步幅，落地脚有支撑阶段，检查膝踝弯曲、脚底与地面/甲板的接触和穿插；不把全身漂移、缩放或晃动当作可动腿动画。站立、步行、登船、坐姿分别检查。
- 操作型道具需要共享接触点：手与桨柄/工具握点、乘员与座位/甲板、船舷遮挡和航行方向；静态握持姿势正确不等于整段划桨正确。动作样例未验证时不得宣称完成绑定或联动。
- 道具可增加服务辨识和动作的结构细节，如船舷、板缝、座位，但不堆积细纹与装饰。裁切后按最终使用尺寸检查清晰度；狼羊等角色保持腿部可分层的轮廓，不因升级美术取消原有动作。
- 角色身份优先靠造型和情境区分，避免给品牌NPC添加无必要的“讲解者”等重复身份标签；项目用户要求的文字仍按实际约定。
- 外部作品数据要标明用户提供/独立核验以及对应作品，不能把别期表现写成本期实测，不能以冷启动时间简单断定表现或保证优化收益。
- 开头优先在首个有效画面呈现该题核心冲突；品牌可叠加，不用无关开场占用钩子。优化前十秒、减少重复讲解，保持题设完整和动作可读；不能为了短而把登船/航行/卸载硬压进单字。
- 三秒思考应有明确问题和完整思考时间。互动邀请不等于观众能在三秒内完成评论，不宣称必然提高互动；不因平台泛化建议机械添加衍生题，避免破坏单题节奏和题目去重。
- 新规则/实际失败经验写回本规范时只保留可复用结论；具体用户决定、截图、播放数、试验结果、生成提示词及素材指纹分别留进度库或素材库，不把项目日志复制到Skill。

### 组件动画与剪辑的实际防错门禁

- **镜像不等于负缩放旋转**：相似变换中的负比例可能把图片旋转180°。反向行走/返航要明确水平反射源像素与锚点，并分别抽查两个方向的实际编码帧，不能只验证正向或只测坐标。
- **裁框不等于干净组件**：同一生成素材板上的船、桨、手、衣袖很容易互相进入裁框。按真实外形做局部遮罩；前景遮挡层也必须与主体alpha相交。检查“只有一支桨”、无残留邻近道具/重复肢体，再做长片。
- **动作质量不是几个零误差数字**：先做短片覆盖装载、上下船、正反向划行、卸载。模型要记录真实输出握点/脚点，检测值从这些点计算，禁用写死的零值。避免局部变量复用导致把源图锚点当世界坐标。数值通过后仍须看编码画面；有限拆层关节不能宣称通用全身绑定。
- **剪声音先保护语义边界**：保留原WAV时，选段的前后余量不能夹入已删除的上一句尾音或下一句开头。依相邻声学边界约束/静音处理余量，记录原文件散列、样本区间和精确偏移；不要用整段加速代替节奏编辑，也不要把原机器估计字时长称为重新人工校准。
- **首帧和尾部一起算节奏**：正文首屏有冲突，不代表最终视频首帧已有冲突；拼接品牌片头后必须检查最终0秒画面。删重复回放后保留题设、推理必需动作与已约定的完整思考时间，保证图、声、字幕来自同一剪辑时间表。
- **最后一次处理后重验散列**：首帧覆盖、重封装、重混音之后，旧解码报告不再代表最终文件。重新全片解码、读取编码参数、抽查实际帧、核对字幕文字与音频编辑表，再生成发布包校验；保留“未完整人工试听”“待用户审阅”等真实边界。

### 用户审片后的补充门禁

- 开场优化不得擅自遮盖、替换或删除已确认的品牌片头/片尾。要改变其长度、位置或画面，先说明并取得明确授权；检查当前品牌目录，不能凭印象选旧版片头。
- 几何示意升级为具象组件时，清查遗留的座位圈、占位符、辅助线和重复规则标记。它们在旧图里能解释概念，不代表叠到真实造型上仍能被理解。
- 胳膊手脚不能只在全景缩略图验收。关节须有局部放大、连续正反向动作检查；站姿组件若不能自然转成坐姿，就换专用姿势素材，不靠极端拉伸硬套。
- 竞品开场研究必须标明实际可访问内容：检索到标题不等于观看视频，搜索页导航不等于视频样本；拿不到片段时请求链接/录屏。创作建议和实际观察分开，不编造平台惯例、成功率或留存因果。

- 指定创作者研究先核对账号ID/主页关联，避免同名账号或仿制教程混入。使用关联跨平台作品时明确实际平台与版本，不能默认剪辑一致；抽帧能证明画面观察，不能冒称完整听审或证明留存因果。品牌版本能从规范与catalog恢复时先自行查找，不把恢复工作转交用户。

- 坐姿动画要同时核对坐骨/座板承重、脚部遮挡和桨入水位置；只把脚对齐站立甲板线，可能导致整个人悬坐在船上方。两姿势直接交叉淡化会造成双脸、双帽沿或双手，优先使用一致纹理的关节/局部变形并检查中间帧。
- 取消独立片头时审计共享导出器：拼接、音频、SRT和字级JSON可能分别硬编码片头时长。必须一起改为实际偏移，不能只裁画面而保留字幕偏移；未改完前禁止使用旧默认完整导出入口。不要假设给对象添加work之类的属性就能改变辅助函数硬编码的工作目录。

## 9. 解谜短视频结构范式（2026-09 参考研究沉淀）

来源与方法见 `references/reference-study-playbook.md`；账号身份、抽帧、ASR、播放快照等证据只在私有进度库。以下为通用制作规则；凡与用户已确认的品牌决定冲突之处，以进度库中的用户决定为准。

- **双层标题**：每期登记一个 ≤4 字的“局名”（机制/道具 + 局/陷阱/迷局/死局/赌局，如“七天金条”“三灯盲局”）与一个完整问句式平台标题（具体情境 + 具体数字 + 第二人称/挑战，≤30 字，不泄底）。局名写入 catalog 与发布文案；是否替换现有封面主标题需用户确认。
- **首 20 秒**：首个有效画面就是题设场景与第一句字幕；20 秒内把题设讲完并抛出问句。是否加独立品牌片头仍按进度库现行规则逐期与用户确认（006、013 的取消仅限该期）；参考样本已演变为 0 秒片头，可向用户建议把“无独立片头 + 左上角标 + 3 秒片尾”设为系列默认，未获确认前不得自行改变默认。
- **剧本五拍**：题设 →（常见错误思路 1–2 个并说明为何不行）→ 破局点一句话 + 逐步操作 → “为什么这样一定正确”证明（分案/公式/表格）→ 命名原理（4 字或短语）+ 1–3 句格言收束。可选“有人可能会问…”预答疑。缺拍要在分镜说明理由。博弈两难类无唯一解时以反问收尾，不硬造答案。
- **时长**：单题目标 100–150 秒；超过 150 秒先删重复讲解、合并对称步骤，多步搬运题优先压缩步骤而非加速；改音色或倍速须用户确认。剧本按 280–330 字/分钟估算，与实际配音时长核对。
- **舞台式动画**：一期一个舞台，少硬切；每一步在画面上写明“谁/哪个/多少/什么状态”：编号、锁/勾/叉、绿章（正确/安全）、红色瞄准圈、虚线高亮框、计数器、日历、示数、案例标签（情况一/情况二）。所有标注取自同一确定性状态模型。规则单独放白色规则卡，关键词变色。
- **错误示范**：用路人角色代表“普通人的第一反应”，配红叉，回退后恢复初始状态；不与正式操作计数混在一起。
- **思考拍**：保留用户已批准的白卡黄环 3 秒“3、2、1”；参考样本另有“整幅压暗约 45% + 中央大数字约 2 秒、旁白不停”的做法，可作为用户可选项，未获确认前不替换。
- **字幕**：逐字声学对齐与用户批准的白字黑边、逐字黄高亮样式不变；显示行按短语级切分（5–12 字一行，按语义断句），不整句铺满；SRT 仍导出句级。
- **命名原理**：结尾原理名（如“逆向归纳”“不变量”“以终为始”类）写入 script.json 与发布文案，作为置顶评论/简介关键词；不得照抄参考账号的原创格言文本。
- **响度交付门禁**：每期成片测量整体响度、LRA、真峰值并写入 QA；全系列保持一致目标（建议整体 −16～−14 LUFS，真峰值 ≤ −1 dBTP），不追求重压限。
- **题库差异化**：新选题除自库查重外，还要核对私有 catalog 中的 `reference-coverage-*.json`；同机制题若参考账号已发布，提案中必须写明差异化角度（题设情境、呈现方式、切入点），或优先选未覆盖机制。
- **换皮不换机制**：经典题可换成当代情境（职场、外卖、红包、遗嘱等），实体用“名字+属性+数字”命名；换皮后机制、状态模型与逻辑校验不变，catalog 的 puzzle_key 仍登记原机制，查重按机制判断。
- **题设显式理想化 + 预答疑**：题设中用一句话说明理想化假设（“所有人绝对理性且知道彼此理性”“规则一定被执行”），并在证明段后用“有人可能会问…”回应最可能的反驳；提问句 ≤20 字，能被观众复述。
- **推理/排除类画面**：候选对象常驻一行不消失；排除=先灰化再红叉；考虑中=虚线框；人物陈述做成常驻对话卡供引用。
- **错误思路算到底**：错误方案要执行到失败结果并给出具体数字/状态，再回退；不能一句“行不通”带过。
- **模板与工具**：起稿用 `templates/script-five-beat.md`，分镜与渲染遵循 `templates/stage-layout-spec.md`，标题/封面按 `templates/cover-title-formula.md`；配音前跑 `tools/script_budget.py` 估时并检查五拍与字幕行长。
- **成片基准 QA（写入每期 QA 记录）**：①首个问句 ≤20s；②有思考拍；③每个操作步至少一个画面标注；④有“为什么一定正确”段；⑤原理名 ≤4 字且写入 script.json；⑥总时长 100–150s（超出需用户确认）；⑦整体响度/真峰值符合系列目标。任一项不达标须在交付说明中写明原因。
- **不克隆**：不使用参考账号的人物造型、面具/剪影、片头片尾、封面底图、旁白文本与音轨；只吸收结构、节奏、标注与命名逻辑。

## 2.6 封面规范（三版式 3:4 / 4:3 / 16:9，2026-09-20 用户定版）

版式对标参考账号 B 代“白底图标卡”，只学版式不复用其素材：
1. **每期必须同时输出三种版式**：3:4 = 1080×1440、4:3 = 1440×1080、16:9 = 1920×1080；纯白底；同一道具、同一局名、同一字体，仅布局参数不同（见脚本 LAYOUT 表）。
2. 上部 10%–50% 高：**居中单个扁平彩色道具图标**（生成图，粗黑描边、贴纸风、白底抠透明），道具是本期唯一彩色元素，只用 1–2 种柔和主色（黄/红/蓝）。
3. 中下部：**4 字局名**，粗宋体（NotoSerifCJK-Bold）黑字 + 白描边 + 软阴影，字距 1 空格；字号自动缩到宽度 ≤ 86% 画布，**禁止出边**。
4. 底部 88% 处一行灰色小字系列名（“墨问 · 逻辑局”）。
5. 封面不出现答案、不复述题设；局名 + 一个道具即可。全系列同版式同字体，改版一次性全换。
6. 工具：`scripts/make_cover.py <道具png> <局名> [系列名] [输出目录] [ratios]` → 输出 cover-3x4.jpg / cover-4x3.jpg / cover-16x9.jpg；交付前必须 read 三张成图自审（出边/道具偏灰/文字压图/3:4 下宽道具是否过小）。
7. **道具必须与正片素材一致（2026-09-20 用户强调）**：封面道具只能取自该期正片实际使用的 sprite/art（从 art/ 或从视频帧抠图），**禁止另生成一套风格不同的新图标**。方法：读帧 → 按背景色阈值抠 alpha → 去掉字幕框/标签/道具之外的杂像素（自审放大检查）→ 组合成一个主道具。
8. **容器类道具（船/桌/盘/盒）里的物件必须真的"在里面"**：把容器拆成"远侧"和"近侧"两层（对单张 sprite：近侧 = 下半部分 alpha 复制层），绘制顺序 远侧 → 物件 → 近侧，物件脚线落在容器内底面（约容器高度 60% 处）。禁止把物件直接叠在容器顶部边缘上——看起来像站在船外/桌外。成图后必须放大自审。

### 舞台密度与样例门（2026-09-21 沉淀，019 成片废弃复盘）
1. **密度基线对照**：新期渲染前抽同系列已接受成片 3–5 个编码帧，量测组件数/画面占比/分区数；新期设计帧同口径量测并写入设计文档，低于基线不开渲。俯视几何题不豁免。
2. **组件事件密度**：按每 5 秒窗口统计新增或变化的视觉组件；任何 >5s 窗口无组件事件即设计缺陷。“空感”来自时间分布，静帧自审发现不了。
3. **拍-组件清单**：开机列组件清单并对拍：每个叙事拍至少一个专属组件或状态图；组件数 < 拍数先补生成，再进渲染。
4. **样例门**：视觉方案新建或大改后，先交 10–15s 样例片（含 2–3 个叙事拍）给用户确认，确认后才允许全片渲染；未经样例确认的全渲视为浪费而非进度。
5. **观感自审项**：自审表必须含整体观感（空/富/单调）与同系列已接受帧并排对照两项；只有准确性条目（遮挡/可读/响度/几何）即判自审不过。

## 热点共情与参与门
1. **具体的人与在意的事**：起稿先写一句“观众想做什么，担心什么被打断”。用可见的道具与操作承载，不用“大家一定都懂/所有人都被坑”冒充普遍事实；不为制造痛点虚构真实机构违规或额外灾难。
2. **开头默认同时过“代入感＋主题”门**：先把观众放进一个具体场景：正在做什么、想得到什么、下一步要怎么选、选错有什么可感后果。不能只在旁白加“你”字，也不能只报物件和规则。优先用“眼前任务与核心限制→观众的直觉操作→明确代价或冲突→邀请选择”的次序，愿望与操作必须由本题道具承载。前5秒仍须带出任务锚、具体物件/数字；完整题设和首问仍≤20秒，不用一段背景故事换代入感。梗在题设之后，来自操作或结果，不抢主题、不靠无关段子补开场。主题可以前置，具体解法不要提前泄露。
3. **参与闭环**：题设给齐→观众先选/先猜→完整思考拍→错误直觉具体演到失败→揭晓回到最初选择→可选低负担回忆/理由问题。视频中的心里选择不等于已制作可点击互动系统；不假定三秒内能发完评论。
4. **推理公平**：与结论有关的前提揭晓前交代；不要把隐去条件、偷换概念或临时改规则当反转。梗、道具、角色动作不改变逻辑状态，除非显式建模。
5. **结尾回到观众在意的事**：先留在本题情境，再决定是否迁移。不为套模板强插另一个题材；只证明四条记录就不能拍出全公司合规、所有人放假成功的结局。
6. **自审用证据而非形容词**：列出共情触发点、参与动作、线索充分性、思考时长、揭晓回扣与新增/删减镜头。区分设计预期、用户主观反馈和实测数据，不宣称“必爆”“必共鸣”。用户提出优化方向不等于稿件或媒体已获放行。
7. **幽默服从清晰**：不为了凑固定梗数破坏证明；用户把共情作为当前优化重点时，记录梗密度变化与取舍，再请用户评审，不把估计的笑点数量称为实际笑声或互动效果。

### 口语化与主动猜谜
- 以“观众下一步要选/翻/查什么”组织旁白；用一个具体错误操作和可见后果，替代“充分必要、验证前提”等抽象说明。保留完整逻辑，但不要求观众先学术语。
- 减少替观众总结人生道理。用户要求少说教时，原理名可仅作画面轻标；结尾回问本题的选择，不强插格言或跨题迁移。
- 可在同题中增设中途选择，但必须显式交代已经知道什么、还剩哪些选择、还剩几次操作；观众猜完再揭晓。不为了参与感临时更改规则或给出题设禁止获得的信息。
- 把“求最少次数”改为“最多N次挑战”时，仍验证预算内能保证判定；错误示范、重置、正确尝试须区分。名额耗尽后不能为讲解偷偷执行额外观察；充分性证明可用已知标签与明确假设，不伪装成合法额外操作。

### 已批准封面版式复用与多音字返修
- 复用系列封面不能只核对白底、字体、色彩等描述；必须读取已批准封面原图及模板，逐项核对道具/局名/系列名的上下顺序、尺寸占比、留白、描边阴影和固定系列文字。画布比例正确不等于风格一致。新增问句、分割线或翻转标题与道具顺序属于版式变更，不得夹带。
- 用户指出读音错误后，以反馈定位原音与处理版，重新打开该句的发音审核。ASR字面一致不能证明多音字声调正确。例如“假”在年假语义读jià，在真假语义读jiǎ；短语“查假”有歧义，不宜仅凭识别文本判过。必要时提议改为明确语义的上下文，用户确认文字改动后只修对应段，重做该段声学对齐及后续时间映射。
- 一遍理解能力不得用逻辑穷举通过代替：分别核对观众需记住多少次重置/假设、卡片翻面后身份能否持续追踪、结论是否使用日常具体行为表述。未做目标观众测试，只能报告理解风险，不能保证“一遍就懂”。


### 自然配音：先选声，再确认成片语速与停连
- **两道试听门**：音色对比只确认声音偏好；选定后，用实际稿件录一段含叙述、规则、转折和提问的短样，按项目已批准语速处理后再次试听。音色通过不等于变速后的自然度通过，也不等于整篇配音通过。
- **声音合适、节奏生硬时先修表达方式**：保留已选声音与已批准字词，优先调整句子分组、标点引导、语义停顿和强调；必要时重录，不机械地重新选声或一味提高倍速。字词改动须另获确认。
- **按语义组织呼吸**：规则、反例和提问之间留清晰停顿，减少句内无意义的碎停顿；不把每个逗号念成同等长度，也不把所有静音压成同一极短值。思考拍是独立事件，不可作为普通静音裁掉。
- **参数不是通用审美答案**：停顿上限与tempo应按样段实测，在已批准的语速/时长/处理幅度范围内选择；某次有效的停顿参数不能升级为全系列固定值。保留原始音频、精确裁切映射、处理参数与试听版本，便于回退。不可用“去停顿”名义裁掉语音。
- **技术与听感分开验收**：真实时长、字速和波形峰值是技术门；自然、不赶、重点清楚由实际试听确认。没有听审不能宣布已自然，ASR文本一致也不能证明重音、情绪或多音字正确。
- **换声一致性**：更换成片旁白音色时统一全篇，不混用旧声；优先保留新声已通过的短段，剩余段按同方向录制。新增录音须重新声学对齐，字幕、动画锚点和思考拍全局时轴随之重建。
- **克制原则**：不要用夸张播音腔、连续重音、密集音效去掩盖理解负担。图表承担结构化总结，字幕承担听读对应，音效只强调必要事件，不能三者同时争抢注意力。


### 全文读音门与用户反馈后的重开审查
- 用户指出一处读音错误时，不将问题局限于该时间点。先扫描全文同词、同字的相关词组和不同语义用法，列出每次出现的位置、上下文、标准读音、音频源与声学时间，并重新检查全部相关段落。
- 多音字按语义区分。例如年假、请假、批假中的“假”读jià；假设、真假中的“假”读jiǎ。自动拼音工具或ASR只能辅助查漏，不能独立裁定语境读音。
- 内容识别、词典读音、实际声调听审是三项不同证据。识别出了原字，不代表读对了声调；识别成同音字，也不能独立证明读错。不把词组扫描或时间定位写成“全文发音已通过”。
- 首先保留已选音色和已批准原稿，调整朗读上下文或局部重录。若服务支持明确读音控制，按服务允许格式使用；不向仅支持纯文字的接口塞SSML或指令标签。需要改正文避免歧义时先取得用户确认，不擅自改稿。
- 修复按最小必要段落进行，保留原音与版本映射；修后复核相邻剪接口、语速、自然停连，并重做受影响段声学对齐及后续全局时轴。所有同词出现都应有明确复核状态。
- 用户读音反馈会重开音频验收；先前选声、短段或全篇批准不自动覆盖新录音。工具配额耗尽时写清待修范围与下一步，不生成虚假的修复结论，也不要求用户承担全文检查。

- 若纯文字语音接口需要同音字辅助指定声调，只能作用于独立的生成输入；正式原稿、字幕、发布文案和声学对齐目标必须使用原字。私有工程保留逐项映射、实际取样版本与修改理由。同音输入不是正确读音的保证，仍须实际试听；不得因此宣称全文声调已通过。


### 字幕行尾不带标点
- 常规旁白字幕每条显示行的末尾不显示逗号、句号、问号、感叹号、冒号、分号、顿号、省略号等终止标点；句中有助于理解的必要标点保留。
- 此为显示层规则：原始口播文案、TTS断句、声学逐字对齐、字幕开始结束时间均不因去标点而改变。渲染字幕与交付SRT保持一致。
- 不对所有画面文字全局删标点。图表问题提示、规则符号、数字小数点、比例、单位、引用内容等具有语义作用的符号按原意保留。
- 导出前检查每个字幕块的文本末尾，确认无常规句末标点残留，同时检查逐字高亮映射未因显示文本变化而错位。


### 长期默认制作规范（用户明确采用）
以下为后续制作的默认方法；用户对具体任务提出的新要求可覆盖相应项。固定的是验收原则，不是某一集的剧情、图表布局、声音ID或处理参数。
1. **自然停连试听**：选声后再听实际成片语速的短段。声音合适时优先修句子分组、停顿与强调；不靠一味加速解决时长，也不机械地把所有停顿压成同一长度。
2. **全文读音复查**：指出一处读音错误就排查全文同词、同字不同语义，逐处定位并复核。词典、ASR、输入读音提示和实际听审分别记录，不能互相冒充。
3. **字幕行尾无标点**：画面字幕与SRT一致，去常规行尾标点；句中必要标点、图表问号和数学符号保留。原稿、配音、逐字时标不因此改动。
4. **颜色表达明确状态**：颜色和文字标签共同说明含义，由同一逻辑状态驱动。默认用小面积红色表示已确定的错误/违规，黄色表示待查、注意或选择成本，绿色表示已验证范围内通过；不得把“检查策略不合适”标成“对象违规”，也不得把局部通过扩张为整体通过。具体题目可调整配色，但同片含义须一致且不能只靠颜色传递信息。
5. **图表跟随讲解**：适合用图表时，按口播或操作顺序逐项出现、连接并收束；不突然塞满静态表格，也不为了套模板强加图表。具体布局、信息量与动画服务于当期题目，不复用上一期的结论结构。
6. **音效克制**：仅在必要操作、思考或结论事件使用少量提示；轻淡入、短距离移动等优先于高强度效果。不能让字幕、图表和音效同时争抢注意力；不要求每句、每字或每个图形都配音效。

这些默认方法不豁免当期逻辑门、实际语速和时长检查、样片确认、全片终审与远端同步核验；也不代表已经做过观众一遍理解的测试。

## 轻解谜与15秒回报门（当前优先）

后续选题、文案与分镜执行 `light-puzzle-experience.md`。每15秒需要可辨认的包袱或爽点；以具体信息增量核验，不以纯切镜/音效计数。保持现行85–120秒、320–340字/分钟、完整首问≤20秒、逻辑门与用户审批；规则太密先简化题设，不靠加速或隐藏小字。旧固定笑话配额、首句全部条件、强制长错误分支不再优先。
