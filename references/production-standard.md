# 墨问通用制作标准

适用于今后任何模型。此文记录可复用的默认规范；具体任务选择及后续变更读取统一私有进度库。不要把历史示例的近似字幕、旧人物、右上标语重新带回。

## 1. 品牌与人物分场景使用
- 品牌只有“墨问”，不再二选一。成熟、酷、非真人感；拒绝幼稚大头墨滴，不模仿别人的角色或署名。
- 主页头像/背景可以保留精细水墨美术；视频正文与片头片尾统一灰底、简化黑白线稿人物、黄色逻辑道具。不把写实山水水墨片头硬接简笔画正文。
- 视频NPC身份标识：无脸黑头、一道斜白线、高领、黑白长衣，成人比例。讲解/思考/指向/摊手揭晓四姿态由私有项目配置提供路径。
- 全程单一姿势不合格；按提问、分析、操作解释、揭晓切换关键姿态。不得用整个人物晃动、漂浮代替表演。
- 使用多关键姿态时，不得宣称已经完成连续关节绑定。拿取、点火、翻面等角色动作必须有真实接触点和道具状态支持，没实现就不宣称实现。
- 墨问为讲解者。蒙眼/失明等故事中的参与者不能因为讲解者可见图而获得不允许的信息。

## 2. 画面与字形
- 默认16:9、1920×1080、30fps、H.264/yuv420p/AAC/faststart。核心几何与字体直接绘制到1080p，不以单纯放大编码冒充原生细节。
- 背景 #bdbdbd，轮廓 #252525，重点 #f7ca54，白色区域 #f8f8f5。黄色是强调色，不是所有具象物件的唯一颜色；可使用低饱和木色、灰蓝、植物绿和自然肤色，限制同时出现的主色数量并保持黑白灰画面层级。
- 正文左上只放“墨问”两字，不带编号、斜杠或系列副名；正文右上不放“理想化逻辑题”等常驻长标语。必要题设、安全边界仍须在正文相关场景或发布简介中清楚给出。
- 所有精确文字、数字、数量图和公式用代码绘制。不要采用生图里看似正确的随机文字/硬币数量。
- 明确选择简体中文字形。NotoSansCJK的TTC合集要验证具体face，当前环境 SC 为 index=2；不能盲用默认JP face。环境变更时重新核实，不能永久假定index=2适合任意字体。
- 全文检查标题、字幕、角标、计数、封面、片头片尾及发布简介中的错别字和条件矛盾。“墨”为U+58A8；字形地区差异不等于源字符编码错误。

### 2.1 小屏可读性门禁（用户审片反馈沉淀，2026-09）
- 讲解者形象默认不常驻正文；舞台主体居中放大。
- 同屏 ≤2 行大字（≥52px@1080p），字幕 ≥72px；不出现小字规则卡/公式/汇总板。
- 交付前把 ≥5 个关键帧缩到 640×360 复查，任一数字/文字看不清即不通过。
- 长段配音（>60s）逐字对齐可能在中途失锁：按句群 ≤40s 分段合成再对齐，并检查零时长字与事件锚单调。

### 2.2 交付前终检（Final Quality Gate，用户审片反馈沉淀 2026-09）
交付前必须逐项打勾并写入 QA 记录，任何一项不过即不交付：
1. **插画而非几何图形**：每个关键状态（题设物件、每一步操作后的状态、结论态）都是生成插画（同一风格、同一物件跨状态一致），不能用代码圆/矩形代替实物；代码只画标注（数字、箭头、勾叉、框）。
2. **角色有脸有反应**：故事角色有简单五官与至少两种表情态（平静/困惑或惊讶），并在关键节拍切换；不用“无脸复制人”。
3. **克制的颜色**：颜色只点缀关键物件（1–2 处，如果酱、药片），人物与场景保持黑白线稿；状态色（红/绿/黄）只用于标注。全灰单调与整幅上色都不过。
4. **场景底**：物件放在桌面/地面/场景底上，不悬浮。
4b. **计数正确性**：凡表达数量的生成图（N 块、N 个、N 条线）入片前必须逐张人工数数并记录；生成模型常少画/多画。数不对就重生成，或在整体图上由程序精确绘制分割线。
5. **参考对照**：把 ≥4 张成片关键帧与参考账号同类节拍的帧并排（`tools/study_frames.py` 或手工拼图），逐项对比人物/物件/颜色/文字量/结尾，写出差距与处置。
6. 小屏可读性（§2.1）、逻辑断言、validate_video、响度 —— 沿用。
7. 片头片尾按项目品牌决定（可无片尾）；若无片尾，正文最后一句后留 0.6–1.0s 静止再结束。

### 2.3 交付前自审（Self-Review，2026-09-20 沉淀）
用户的反馈不应是第一道质检。每次交付前，制作者必须**自己先当审片人**，逐帧看完事件帧并按下表量测，不合理处自己改掉再交付。以下每一条都来自真实返工：

| 坑 | 症状 | 规则 |
|---|---|---|
| 每个状态各生成一张图 | 同一物件在不同状态里大小、风格、盘子都不一样；“一刀两块”被画成“挖走一块” | **单源派生**：只生成 1 张基础物件图，量测其几何（椭圆中心/半径、腰线、壁线），所有切割/拆分/移动状态由程序在同一张图上切片、错位、补截面得到。生成图数量 = 物件数，不是状态数 |
| 场景底只是“放上去” | 蛋糕悬在桌前、脚下无接触 | 量测底图可放置区（如桌面行区间），物件底边必须落在区间内，把量测值写进 state-model |
| 动作特效手写坐标 | 刀光/切线与图里的切缝不重合，刀穿桌 | 动作路径必须由同一几何函数生成（切缝 = 刀路），运动终点受实体边界钳制 |
| 生成的计数图不数数 | “7 块”图只有 5 块 | 见 §2.2 4b；或改成程序精确绘制 |
| 布局靠眼睛 | 字幕压住角色 | 渲染器记录所有元素包围盒，`--preview` 自动报告与字幕带/彼此的重叠，为零才交付 |
| 只看事件帧 +0.9s | 动作中途的错误（刀反向、穿模）看不到 | 事件帧至少看 +0.25s 与 +0.9s 两拍；有运动的事件再加中途帧 |
| 可切/可拆物件带装饰 | 蜡烛正好在切缝上被劈成两半，开场就自相矛盾 | 生成基础物件时，装饰（蜡烛/樱桃/logo）不得压在任何后续切缝/拆分线上；能省则省，或放进某一块的内部 |
| 自审只做“抽 4 帧看看” | 用户一眼看出多处不合理 | 自审产出一份量测表（问题/量测值/根因/处置），存进度库；没有表就没有自审 |

### 2.4 文案对标（参考账号文案结构，2026-09-20）
参考账号 6 篇 ASR 量测出的固定结构，新期文案逐项对照：
1. 一句钩子（≤25 字）：第二人称 + 极限情境 + 赌注；不要"生日会上，一个蛋糕"式的第三人称旁白。
2. 规则 3 句 + "你会怎么选/切"（可给 A/B）。
3. 先把观众放进错误答案："如果你也这么切，恭喜，你已经掉坑里了"，而不是"大多数人会…"。
4. 揭晓一句一个动作，数字口语化；句长 ≤15 字，禁"真正的问题不在…而在…"式书面转折与解释性从句。
5. 一句原理 + 一句生活迁移。
6. 收尾口令：短、对仗、可截图（"记住：…"）。
7. 语速 320–340 字/分钟；90–120s。文案写完先按此 7 项自评，再进 `script_budget.py`。

### 2.5 三项硬约束：语速 / 文案风格 / 时长 必须与参考账号一致（用户强要求，2026-09-20）
不满足任一项不得交付；三项都要在 publish.json 的 `consistency_targets` 里写目标值与实测值。
| 项 | 目标（量测自参考账号 54 篇 ASR） | 怎么保证 |
|---|---|---|
| 语速 | **320–340 字/分**（纯说话段，中位 325） | 1) 先数文案字数 N；2) TTS 后把 >0.2s 的停顿截到 0.2s（TTS 自带停顿常占 20–30%）；3) 需要的 atempo = 截后时长 ÷ (N/325×60)，允许 1.1–1.35；4) 对齐后用逐字时间反算实测 cpm 写入 |
| 文案风格 | §2.4 七项结构（第二人称入局、一句钩子、先打脸直觉、动作化揭晓、原理+迁移、口令收尾、句长≤15） | 写完逐项自评；任何一项不满足就改稿，不靠语速补 |
| 时长 | **85–120s**（参考中位 ~120s，短题 85–100s） | 由字数决定：N = 目标秒数 × 325 ÷ 60（90s ≈ 490 字，100s ≈ 540 字）；思考拍 2–3s、句间 0.3s、结尾 0.8s 静止已含在内 |

## 3. 音频、逐字字幕、倒计时
- 优先复用已有干净WAV和已授权音色，不为改画面重新TTS；新配音仍按当前工具规则先选声，旧voice_id不保证有效。
- 先测量实际配音及提速后的音频，再建立共享时间轴。声音、字幕、计数、角色、道具全部使用这条时间轴。
- 字幕必须依据干净配音做中文逐字声学对齐（forced alignment/可靠ASR字时间）。禁止按句时长平均分字，却声称逐字对齐。
- 对齐输入用准确原稿；保留逐字JSON、对齐方法和可疑边界记录。静音要从字范围中剔除，连读/轻声/零时长字应复核。机器估计不是逐字人工听审后的零误差。
- 显示效果：逐字轻弹入，可短暂黄色高亮，保留句尾阅读时间；不要剧烈跳动。导出句级SRT和逐字时间JSON，说明SRT本身不含弹字动画。
- 中间完整3秒“3、2、1”，一秒一拍，配克制提示音。插入静音必须同步顺延后面的所有字幕、旁白、场景和导出数据。
- 片头约1秒、片尾约3秒；正文时长服从内容。历史四片药较短，不为凑满两分钟无意义拉长。
- 音效用于点火/翻面/步骤/揭晓，不每字一响，不喧宾夺主。音效节点也应来自配音和动画实际事件。
- 低调悬疑氛围BGM可用原创合成或有授权素材；不提取参考创作者音轨。约−25dB是本次底乐音源的增益，不是整体−25LUFS或恒定比人声低25dB；注明参考，混音后检查峰值和听感。人声出现时可额外duck约4dB。
- 保留旁白清晰度和结尾尾音；不能把技术解码成功描述成完成了人工听感验收。

## 4. 动画与逻辑不得互相矛盾
- 操作、身份、数量、正反、燃烧状态由同一确定性状态模型生成；计数器取画面实际状态，不独立猜数字。
- 旁白尚在解释初始状态时，画面不能提前完成操作。关键事件锚定配音中的对应词/句，如“翻面”“两头一起烧”“30分钟到了”。
- 区分示意静帧与计时演示。未消耗的静止绳子不挂持续燃烧火焰；如果暂停讲解则明确说明。
- 非匀速绳子左右火头的长度推进速度可不同；同时开始后两端经过的时间相同。不能为了视觉对称强行改成长度匀速。
- 时间刻度与长度刻度分开标注；对称时间条的左右边界必须一致。保留非中点相遇。
- 第二阶段绳子剩余单头时间30分钟，双头各经过δ分钟后剩余30−2δ，累计时间30+δ；δ=15时完成45分钟。
- 硬币题：初始10正面不等于翻面后总正面仍为10。k→10−k，另一堆保持10−k；100个物体身份不丢失，未选90个不翻动。
- 药片题：每一片各分一半到两天，不是随意选四个半片。保留成分均匀/可精确等分的题设和现实安全提醒，不能作为现实用药建议。

## 5. 抖音发布素材和封面统一
每期必须提供 video.mp4、cover-16x9.jpg、可选cover-3x4.jpg、subtitles.srt、逐字JSON、发布文案.md、publish.json、QA记录和可重建源码。
- 封面统一同一角色、灰底、简体黑字、黄色分隔线、标题层级、边距。标题讲问题，不提前泄露答案；数量图若画出必须可数且正确。
- 横封面用于横屏视频，3:4封面是主页裁切备选；以实际抖音发布预览为准，不编造平台展示保证。
- 发布文案包括短标题、视频简介、3–5个相关话题、可自然融入的关键词、建议置顶评论、安全/题设提醒。不要伪造“99%答错”、热度或爆款保证。
- 不把简介和标签当已发布。用户未明确授权代发平台时，只交付材料；AI辅助内容标识按平台实际可用功能如实设置。

## 6. 版本、交接与存储
- 历史修订保留原编号和原片，不自动新增一期。任务清单、用户是否确认、待办只写私有agent-progress。
- 实际图像、配音、视频、封面、字幕、词级/字级时间、每期文案和项目重建脚本只写私有assets。
- 公开Skill不包含真实执行日志、QA结果、当前任务索引、发布ZIP或历史会话备份。通用验证工具可以公开，运行输出不得提交。
- 发布ZIP只放本次发布素材及素材文件校验清单，不夹入Skill规则、任务进度和历史验证记录。
- 不保存或传播凭据；聊天中暴露过的令牌建议撤销。下一会话不可假定认证仍有效。
- 公开库曾出现私有材料时，删除当前文件不等于删除Git历史。先限制可见性，再迁移干净仓库；未经授权不强推清史，不保证已下载副本可收回。
- 远程提交后核验commit/tree及关键文件hash。只在备份验证成功后清理本地已备份重复件。
- 128MB工作区建议留在110MB以下；按需恢复，不重复克隆全量历史媒体。Git元数据和Python包不保证跨快照保留。

## 拼接与字幕显示边界
- 共用片头片尾的原帧率可能不同，最终拼接导出必须显式指定30fps，之后用实际流/帧数复核；不能在QA中仅写预期帧率。
- 句尾阅读停留不得跨过下一句开始时间。烧录字幕与SRT均取min(本句结束+停留,下一句开始)，避免上一句遮挡新句的首字。

## 动态演示与过渡状态验收
- 动态应来自实际推理操作、因果反馈和局部重点，不用人物整体晃动、无关粒子或持续换文字冒充动画。
- 运输、装卸、拿取等题目必须验证完整过渡过程，不只验证起点和终点。对象身份、所在位置、载荷限制和参与者状态应来自同一模型；不能让道具瞬移、复制或悄悄消失。
- 脚部与甲板/地面、手部与桨柄/道具等接触点应共享坐标；有操作者的空载返程不等于无人驾驶。
- 错误方案须明确标注为假设演示；回退后恢复正确初始状态，不混入正式操作计数。局部放大或回放要标明用途，不能让同一物体的第二视图被误读为新增物体。
- 连贯回放也需给装载、移动和卸载留出可见时间。若口播过密，应调整对应回放文案/配音或整体节奏，不把完整动作硬塞进一个字的时间。
- 白色/浅色主体不能与同色特写底板混成一片；导出后复查实际编码帧，而不只检查渲染前截图。
- 逐字对齐出现零时长或异常密集的边界时，记录问题并使用声学信息复核；修复保留方法与范围，不退回按句均分。机器ASR结果不冒充人工听审。

## 7. 组件图像：生成＋抠图（强制规则）
- 视觉组件（人物、动物、植物、食物、药片、球、石子、昆虫、门、灯、开关、帽子、车辆、绳、温度计等具象物件）一律使用图像生成产物，抠除背景成透明PNG后合成入画面；严禁用代码手绘几何图形冒充组件。
- 仅“非常简单的元素”可代码绘制：箭头、直线、色块、高亮框、计数器、进度条、精确文字/数字/数量图/公式等必须保证精确的图示。
- 生图只承担美术：不含文字、数字与数量；精确信息仍由代码绘制并锚定确定性状态模型。
- 组件图须记录：生成提示词/参数、源文件sha256、抠图方法（alpha/阈值）、边缘与阴影处理；风格统一灰底、黑色轮廓、黄色重点，与正文简笔风一致。
- 跨期复用按repo+commit+path+sha256引用，不重复上传；旧期若使用代码手绘组件，修订或重做时按本规则替换为生成抠图组件，并在进度证据中登记替换清单。

## 8. 形象确认、图片组件关节动画与节奏迭代
- 用户要求先看形象时，先交静态角色/道具提案，明确尚未完成绑定；确认后再制作动作样例和正式视频。旧片接受不等于新形象或修订版接受。
- 生成图片不会自动产生步态。需要生成适于分层的组件，分别准备躯干、上/下肢、手足与必要遮挡补画，或制作一致的关键姿势；关节变换只操纵生成组件，不用代码画细线四肢替代已批准造型。
- 步行动作按位移驱动步幅，落地脚有支撑阶段，检查膝踝弯曲、脚底与地面/甲板的接触和穿插；不把全身漂移、缩放或晃动当作可动腿动画。站立、步行、登船、坐姿分别检查。
- 操作型道具需要共享接触点：手与桨柄/工具握点、乘员与座位/甲板、船舷遮挡和航行方向；静态握持姿势正确不等于整段划桨正确。动作样例未验证时不得宣称完成绑定或联动。
- 道具可增加服务辨识和动作的结构细节，如船舷、板缝、座位，但不堆积细纹与装饰。裁切后按最终使用尺寸检查清晰度；狼羊等角色保持腿部可分层的轮廓，不因升级美术取消原有动作。
- 角色身份优先靠造型和情境区分，避免给品牌NPC添加无必要的“讲解者”等重复身份标签；项目用户要求的文字仍按实际约定。
- 外部作品数据要标明用户提供/独立核验以及对应作品，不能把别期表现写成本期实测，不能以冷启动时间简单断定表现或保证优化收益。
- 开头优先在首个有效画面呈现该题核心冲突；品牌可叠加，不用无关开场占用钩子。优化前十秒、减少重复讲解，保持题设完整和动作可读；不能为了短而把登船/航行/卸载硬压进单字。
- 三秒思考应有明确问题和完整思考时间。互动邀请不等于观众能在三秒内完成评论，不宣称必然提高互动；不因平台泛化建议机械添加衍生题，避免破坏单题节奏和题目去重。
- 新规则/实际失败经验写回本规范时只保留可复用结论；具体用户决定、截图、播放数、试验结果、生成提示词及素材指纹分别留进度库或素材库，不把项目日志复制到Skill。

### 组件动画与剪辑的实际防错门禁

- **镜像不等于负缩放旋转**：相似变换中的负比例可能把图片旋转180°。反向行走/返航要明确水平反射源像素与锚点，并分别抽查两个方向的实际编码帧，不能只验证正向或只测坐标。
- **裁框不等于干净组件**：同一生成素材板上的船、桨、手、衣袖很容易互相进入裁框。按真实外形做局部遮罩；前景遮挡层也必须与主体alpha相交。检查“只有一支桨”、无残留邻近道具/重复肢体，再做长片。
- **动作质量不是几个零误差数字**：先做短片覆盖装载、上下船、正反向划行、卸载。模型要记录真实输出握点/脚点，检测值从这些点计算，禁用写死的零值。避免局部变量复用导致把源图锚点当世界坐标。数值通过后仍须看编码画面；有限拆层关节不能宣称通用全身绑定。
- **剪声音先保护语义边界**：保留原WAV时，选段的前后余量不能夹入已删除的上一句尾音或下一句开头。依相邻声学边界约束/静音处理余量，记录原文件散列、样本区间和精确偏移；不要用整段加速代替节奏编辑，也不要把原机器估计字时长称为重新人工校准。
- **首帧和尾部一起算节奏**：正文首屏有冲突，不代表最终视频首帧已有冲突；拼接品牌片头后必须检查最终0秒画面。删重复回放后保留题设、推理必需动作与已约定的完整思考时间，保证图、声、字幕来自同一剪辑时间表。
- **最后一次处理后重验散列**：首帧覆盖、重封装、重混音之后，旧解码报告不再代表最终文件。重新全片解码、读取编码参数、抽查实际帧、核对字幕文字与音频编辑表，再生成发布包校验；保留“未完整人工试听”“待用户审阅”等真实边界。

### 用户审片后的补充门禁

- 开场优化不得擅自遮盖、替换或删除已确认的品牌片头/片尾。要改变其长度、位置或画面，先说明并取得明确授权；检查当前品牌目录，不能凭印象选旧版片头。
- 几何示意升级为具象组件时，清查遗留的座位圈、占位符、辅助线和重复规则标记。它们在旧图里能解释概念，不代表叠到真实造型上仍能被理解。
- 胳膊手脚不能只在全景缩略图验收。关节须有局部放大、连续正反向动作检查；站姿组件若不能自然转成坐姿，就换专用姿势素材，不靠极端拉伸硬套。
- 竞品开场研究必须标明实际可访问内容：检索到标题不等于观看视频，搜索页导航不等于视频样本；拿不到片段时请求链接/录屏。创作建议和实际观察分开，不编造平台惯例、成功率或留存因果。

- 指定创作者研究先核对账号ID/主页关联，避免同名账号或仿制教程混入。使用关联跨平台作品时明确实际平台与版本，不能默认剪辑一致；抽帧能证明画面观察，不能冒称完整听审或证明留存因果。品牌版本能从规范与catalog恢复时先自行查找，不把恢复工作转交用户。

- 坐姿动画要同时核对坐骨/座板承重、脚部遮挡和桨入水位置；只把脚对齐站立甲板线，可能导致整个人悬坐在船上方。两姿势直接交叉淡化会造成双脸、双帽沿或双手，优先使用一致纹理的关节/局部变形并检查中间帧。
- 取消独立片头时审计共享导出器：拼接、音频、SRT和字级JSON可能分别硬编码片头时长。必须一起改为实际偏移，不能只裁画面而保留字幕偏移；未改完前禁止使用旧默认完整导出入口。不要假设给对象添加work之类的属性就能改变辅助函数硬编码的工作目录。

## 9. 解谜短视频结构范式（2026-09 参考研究沉淀）

来源与方法见 `references/reference-study-playbook.md`；账号身份、抽帧、ASR、播放快照等证据只在私有进度库。以下为通用制作规则；凡与用户已确认的品牌决定冲突之处，以进度库中的用户决定为准。

- **双层标题**：每期登记一个 ≤4 字的“局名”（机制/道具 + 局/陷阱/迷局/死局/赌局，如“七天金条”“三灯盲局”）与一个完整问句式平台标题（具体情境 + 具体数字 + 第二人称/挑战，≤30 字，不泄底）。局名写入 catalog 与发布文案；是否替换现有封面主标题需用户确认。
- **首 20 秒**：首个有效画面就是题设场景与第一句字幕；20 秒内把题设讲完并抛出问句。是否加独立品牌片头仍按进度库现行规则逐期与用户确认（006、013 的取消仅限该期）；参考样本已演变为 0 秒片头，可向用户建议把“无独立片头 + 左上角标 + 3 秒片尾”设为系列默认，未获确认前不得自行改变默认。
- **剧本五拍**：题设 →（常见错误思路 1–2 个并说明为何不行）→ 破局点一句话 + 逐步操作 → “为什么这样一定正确”证明（分案/公式/表格）→ 命名原理（4 字或短语）+ 1–3 句格言收束。可选“有人可能会问…”预答疑。缺拍要在分镜说明理由。博弈两难类无唯一解时以反问收尾，不硬造答案。
- **时长**：单题目标 100–150 秒；超过 150 秒先删重复讲解、合并对称步骤，多步搬运题优先压缩步骤而非加速；改音色或倍速须用户确认。剧本按 280–330 字/分钟估算，与实际配音时长核对。
- **舞台式动画**：一期一个舞台，少硬切；每一步在画面上写明“谁/哪个/多少/什么状态”：编号、锁/勾/叉、绿章（正确/安全）、红色瞄准圈、虚线高亮框、计数器、日历、示数、案例标签（情况一/情况二）。所有标注取自同一确定性状态模型。规则单独放白色规则卡，关键词变色。
- **错误示范**：用路人角色代表“普通人的第一反应”，配红叉，回退后恢复初始状态；不与正式操作计数混在一起。
- **思考拍**：保留用户已批准的白卡黄环 3 秒“3、2、1”；参考样本另有“整幅压暗约 45% + 中央大数字约 2 秒、旁白不停”的做法，可作为用户可选项，未获确认前不替换。
- **字幕**：逐字声学对齐与用户批准的白字黑边、逐字黄高亮样式不变；显示行按短语级切分（5–12 字一行，按语义断句），不整句铺满；SRT 仍导出句级。
- **命名原理**：结尾原理名（如“逆向归纳”“不变量”“以终为始”类）写入 script.json 与发布文案，作为置顶评论/简介关键词；不得照抄参考账号的原创格言文本。
- **响度交付门禁**：每期成片测量整体响度、LRA、真峰值并写入 QA；全系列保持一致目标（建议整体 −16～−14 LUFS，真峰值 ≤ −1 dBTP），不追求重压限。
- **题库差异化**：新选题除自库查重外，还要核对私有 catalog 中的 `reference-coverage-*.json`；同机制题若参考账号已发布，提案中必须写明差异化角度（题设情境、呈现方式、切入点），或优先选未覆盖机制。
- **换皮不换机制**：经典题可换成当代情境（职场、外卖、红包、遗嘱等），实体用“名字+属性+数字”命名；换皮后机制、状态模型与逻辑校验不变，catalog 的 puzzle_key 仍登记原机制，查重按机制判断。
- **题设显式理想化 + 预答疑**：题设中用一句话说明理想化假设（“所有人绝对理性且知道彼此理性”“规则一定被执行”），并在证明段后用“有人可能会问…”回应最可能的反驳；提问句 ≤20 字，能被观众复述。
- **推理/排除类画面**：候选对象常驻一行不消失；排除=先灰化再红叉；考虑中=虚线框；人物陈述做成常驻对话卡供引用。
- **错误思路算到底**：错误方案要执行到失败结果并给出具体数字/状态，再回退；不能一句“行不通”带过。
- **模板与工具**：起稿用 `templates/script-five-beat.md`，分镜与渲染遵循 `templates/stage-layout-spec.md`，标题/封面按 `templates/cover-title-formula.md`；配音前跑 `tools/script_budget.py` 估时并检查五拍与字幕行长。
- **成片基准 QA（写入每期 QA 记录）**：①首个问句 ≤20s；②有思考拍；③每个操作步至少一个画面标注；④有“为什么一定正确”段；⑤原理名 ≤4 字且写入 script.json；⑥总时长 100–150s（超出需用户确认）；⑦整体响度/真峰值符合系列目标。任一项不达标须在交付说明中写明原因。
- **不克隆**：不使用参考账号的人物造型、面具/剪影、片头片尾、封面底图、旁白文本与音轨；只吸收结构、节奏、标注与命名逻辑。
