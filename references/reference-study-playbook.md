# 参考创作者研究方法与解谜短视频结构范式

本文是通用规则：第一部分规定“怎样研究一个指定的参考创作者”，第二部分是从公开头部账号样本中提炼出的解谜/思维游戏类动画短视频的可复用范式。具体账号身份、抽帧、ASR、播放数据等证据只放私有进度库（如 `evidence/mowen/creator-study-*/`），不写入本公开 Skill。

## 一、研究方法门禁

1. **先核身份**：用用户指定的账号名，核对平台 ID、主页链接、跨平台镜像（如抖音号 ↔ B站 mid）是否为同一主体；同名账号、搬运号、仿制教程一律排除。记录核对来源。
2. **区分四种可得性**：只看到标题 ＜ 看到封面 ＜ 看到抽帧 ＜ 完整试听。每条结论必须标注它来自哪一层。“检索到标题”不能写成“看过视频”；搜索页导航不是样本。
3. **公开访问，不绕权限**：只用未登录可见的公开元数据、封面 CDN 与公开低清流；不破解、不付费代播、不使用他人凭据。取不到时请求用户提供链接或录屏。
4. **全量元数据 + 分层抽样**：先拿到全部作品的标题/时长/日期/播放/封面；再按“头部 N 期 + 与本项目同题 + 低表现 + 时长极值”抽样正片，避免只看爆款。
5. **可复现的量化观察**（工具见 `tools/`）：
   - 封面：全量拼图对照，统计版式代际、文字字数、彩色数量、尺寸分布；
   - 结构：每 2–3s 抽帧拼图；亮度时间序列找片头长度、压暗/思考拍、结尾切换；场景切换计数；
   - 旁白：低清流做机器 ASR，只用于统计节拍与语速，明确标注“机器识别、非人工校对”；
   - 音频：整体响度 LUFS、LRA、真峰值。
6. **结论分层书写**：`样本观察`（可复核的事实）／`助手推断`（可能的原因）／`本项目建议`（需用户决定的写清楚）。播放量是快照，不是留存或因果证据；不得声称“这样做必然涨播放”。
7. **合规与差异化**：研究只吸收结构、节奏、标注方法与命名逻辑；不复制对方角色造型、面具/剪影、片头片尾、封面底图、旁白文本、音轨与配音。若对方账号声明“禁止克隆/搬运”，在证据中如实记录，并在建议中写明差异化点。
8. **题库重叠登记**：把参考账号已发布题目按机制键归类，存入私有项目 `catalog/reference-coverage-*.json`，供新选题差异化参考。它不替代自库查重，但同机制题若对方已发布，选题说明中必须写明差异化角度或改选未覆盖机制。
9. **写回规则时只留通用结论**：账号名、播放数、截图、ASR 文本、广告内容留证据目录；Skill 只更新可复用的制作规则。

## 二、解谜短视频结构范式（样本提炼）

> 样本：某头部“思维游戏”动画账号 2026 年 3–9 月公开 54 期（B站镜像），全量封面 + 12 期抽帧 + 2 期 ASR。以下为样本观察，采用与否见 `production-standard.md` 第 9 节及项目进度库中的用户决定。

### 1. 双层标题
- 封面只放 **4 字局名**：机制/道具 + 局/陷阱/迷局/死局/赌局/绝杀（“百万密码”“三灯盲局”“七天金条”），≤4 字保证信息流缩略图可读。
- 平台标题是 **完整问句**：具体情境 + 具体数字 + 第二人称/挑战（44/54 含问号，40/54 含数字，中位 24 字）。标题不泄底，不复述解法。
- 封面全系列同一版式、同一字体、同一水印位；改版一次性全换，不混用两代。

### 2. 时间结构（中位 131s，90–150s 为主）
```
0s    首帧即题设场景 + 第一句字幕（片头可为 0）
≤20s  题设讲完并抛出问句（“那么请问，你怎么…？”）
10–30s 思考拍：整幅压暗约 45% + 中央大数字/问号，约 2s；旁白可不停
→     常见错误思路 1–2 个（“很多人的第一反应是…但…”）并说明为何不行
→     破局点一句话 + 逐步操作（每步同步更新画面状态标注）
→     “为什么这样一定正确？”证明段（分案：情况一/情况二；或公式/表格）
→     可选：“有人可能会问…”预答疑
→     命名原理（4 字或短语，黄字）+ 1–3 句格言收束
→     品牌尾卡 2–3s
```
- 多步搬运/渡河类题很容易超过 180s，且样本中 >180s 的期播放全部低于中位：先压缩重复步骤、合并对称步，再考虑加速。
- 博弈两难类（无唯一解）以反问/大问号收尾，不硬给答案。

### 3. 舞台式动画
- 一期一个“舞台”，场景硬切极少（多数 ≤5 次/期）；表演靠元素进出、位移、标注变化，不靠剪辑。
- 每一步把 **谁 / 哪个 / 多少 / 什么状态** 写在画面上：编号、锁/勾/叉、绿章“正确/安全”、红色瞄准圈、虚线高亮框、计数器、日历、天平示数、案例标签。
- 规则用白色卡片单独放大，关键词变色；错误示范用多个路人角色代表“普通人”，配红叉，回退后恢复初始状态。
- 讲解者小尺寸出现在下角，做指点/摊手/思考，不遮挡舞台；本项目仍使用自有 NPC。
- 单一彩色重点：道具的自然色（药片黄、红包红、水蓝）之外全部黑白灰。

### 4. 字幕与旁白
- 字幕按 **短语级** 切分（5–10 字一行），关键词变色；也可与逐字弹入并存，但一行不宜超过 12 字。
- 旁白：短句、第二人称、动词开头；样本语速约 300–335 字/分钟，几乎无长停顿。若配音音色偏慢，先削剧本再考虑倍速。
- 剧本五拍模板：题设 → 错误思路 → 破局操作 → 为何必然正确 → 命名原理+格言。

### 5. 音频
- 样本整体响度约 −9～−10 LUFS、LRA≈1.5 LU、真峰值 >0 dBFS（重压限）。本项目不必模仿重压限，但交付前必须测量并记录 LUFS/LRA/真峰值，全系列保持一致，真峰值 ≤ −1 dBTP。

### 6. 旁白话术骨架（6 期 ASR，机器识别）
- 早期开场为固定系列口头禅（≤10 字）+ “今天玩《局名》”，后期直接进题设；二者都在 3 秒内进入情境。
- 实体命名：一个字/一个绰号 + 一个属性 + 一个数字（“穿高跟鞋的丙要 5 分钟”），全程只用这个名字。
- 经典题**换皮为当代情境**（职场打卡、外卖、奶茶、红包、遗嘱、密室），机制原封不动；标题与局名只写新皮。
- 错误思路不是一句带过，而是**算到底给出失败数字**（“加起来 19 分钟，超时”）。
- 转折句式：“真正锁死全局的不是 X 而是 Y”“最有效的方式是做减法”；随后“我们分 N 步拆解”，每步以“锁定/排除/出局/落地”收口。
- 推理类题按“切换到 X 的视角”组织每一步；证明段用“无论…都…”“情况一/情况二”。
- 结尾三件套：原理名（≤4 字）+ “普通人做 X，高手做 Y”对照 + 1–2 句格言。语速 300–345 字/分钟，几乎无停顿。
- 商业化观察：口播广告置于 26%–80% 处，用“回到游戏/言归正传”回收；与制作规则无关。

### 7. 动画与音频微观（5fps 抽帧 + 频谱，2 期）
- 元素进场：弹入并按 ~0.1s 错开；桌面等大件从下方滑入约 0.3s；气泡分三级放大约 0.4s 后再出文字。
- 动作：图标（刀/手）覆盖对象做 0.3–0.5s 动作，随后对象直接变形（整→半）；对象沿路径飞入容器 0.5–0.8s。
- 过渡：0.2s 聚光/白闪单帧后换场；讲解者从画角滑入只在指点时出现。
- 音频：旁白连续、无长停顿；垫乐为低音量持续性铺底；未见明显打击类音效（低清流+机器分析，未人工试听）。

### 8. 题型表现提示（快照观察，非因果）
- 强：单一机制、可视化强、结论反直觉但必然（倒推/不变量/编码/一次操作破局）。
- 弱：魔术式互动、纯观点式博弈概念、多线索推理小说式。

## 三、用于复现研究的最小工具链
- 元数据：平台公开页面/接口；封面走 CDN 直链；正片只取公开低清流。
- `tools/study_frames.py`：抽帧拼图、亮度时间线、场景切换、响度（依赖 ffmpeg 与 Pillow/numpy）。
- ASR：任意本地开源模型（如 faster-whisper small），输出仅作节拍统计。

## 四、能力边界与实现路径（生图 + 代码动画的可达质量）
- 能对齐参考水平的部分：舞台版式、状态标注、计数/公式/表格、逐步状态机动画、压暗思考拍、短语级字幕、封面版式、剧本五拍——这些本质上是数据驱动的 2D 合成，代码可做到精确、可复现，且比手工剪辑更少出错。
- 需要额外投入的部分：人物表演（多姿态、手势、表情）、道具多状态贴图的一致性、音效与垫乐、真人感配音。路径：为每个角色/道具一次性生成姿态与状态贴图库（透明背景、同一设定词），代码按状态机选贴图；音效用少量固定采样；配音固定音色并把语速纳入预算。
- 不追求的部分：模仿对方的人物形象、片头、格言与配音；差异化靠题库（未覆盖机制）、换皮情境、自己的原理命名体系与更严格的逻辑校验（每个断言可被代码验证）。
- 检验标准：新一期成片在“20s 内提问、每步有标注、有为何必然、有原理名、100–150s、响度一致”六项全部达标，并经用户主观评审通过，才算达到可比水平。
